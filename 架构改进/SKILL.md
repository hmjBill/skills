# 架构改进

发现架构摩擦点并提出**深度化机会**——将浅层模块转变为深层模块的重构。目标是可测试性和 AI 可导航性。

## 术语表

在每个建议中准确使用这些术语。一致的语言是关键——不要漂移到"组件"、"服务"、"API"或"边界"。完整定义见 [LANGUAGE.md](LANGUAGE.md)。

- **模块** — 任何具有接口和实现的东西（函数、类、包、切片）。
- **接口** — 调用者必须了解的所有内容才能使用该模块：类型、不变量、错误模式、顺序、配置。不仅仅是类型签名。
- **实现** — 内部的代码。
- **深度** — 接口上的杠杆效应：大量行为隐藏在小型接口之后。**深** = 高杠杆。**浅** = 接口几乎与实现一样复杂。
- **接缝** — 接口所在的位置；可以在不原地编辑的情况下改变行为的地方。（使用这个，而不是"边界"。）
- **适配器** — 在接缝处满足接口的具体事物。
- **杠杆效应** — 调用者从深度中获得的东西。
- **局部性** — 维护者从深度中获得的东西：变更、缺陷、知识集中在一个地方。

关键原则（完整列表见 [LANGUAGE.md](LANGUAGE.md)）：

- **删除测试**：想象删除该模块。如果复杂性消失，它是一个直通模块。如果复杂性在 N 个调用者中重新出现，它是在赚取自己的位置。
- **接口就是测试表面。**
- **一个适配器 = 假设接缝。两个适配器 = 真实接缝。**

此技能由项目的领域模型**提供信息**。领域语言为好的接缝命名；ADR 记录了此技能不应重新争辩的决策。

## 流程

### 1. 探索

首先阅读项目的领域术语表以及您正在触及的区域中的任何 ADR。

然后使用 Agent 工具和 `subagent_type=Explore` 来遍历代码库。不要遵循 rigid 启发式方法——有机地探索并注意您遇到摩擦的地方：

- 在哪里理解一个概念需要在许多小模块之间跳转？
- 哪些模块是**浅层**的——接口几乎与实现一样复杂？
- 在哪里提取了纯函数仅仅是为了可测试性，但真正的 bug 隐藏在调用方式中（没有**局部性**）？
- 哪些紧密耦合的模块在其接缝处泄露了？
- 代码库的哪些部分未经测试，或者通过当前接口难以测试？

对您怀疑是浅层的任何内容应用**删除测试**：删除它会集中复杂性，还是只是移动它？"是的，集中了"是您想要的信号。

### 2. 提出候选方案

提出一份编号的深度化机会列表。对于每个候选方案：

- **文件** — 涉及哪些文件/模块
- **问题** — 为什么当前架构正在造成摩擦
- **解决方案** — 将会发生什么变化的纯英文描述
- **好处** — 用局部性和杠杆效应来解释，也用测试将如何改进来解释

**使用 CONTEXT.md 的词汇来描述领域，使用 [LANGUAGE.md](LANGUAGE.md) 的词汇来描述架构。** 如果 `CONTEXT.md` 定义了"Order"，请谈论"Order intake 模块"——而不是"FooBarHandler"，也不是"Order 服务"。

**ADR 冲突**：如果一个候选方案与现有 ADR 矛盾，只有当摩擦足够真实以至于需要重新审视该 ADR 时才提出来。清楚地标记它（例如 _"与 ADR-0007 矛盾——但值得重新开放，因为…"_"）。不要列出每个 ADR 禁止的理论重构。

还不要提出接口。问用户："您想探索哪些？"

### 3. 质询循环

一旦用户选择了一个候选方案，进入质询对话。与他们一起走设计树——约束、依赖、深化模块的形状、接缝后面是什么、哪些测试会保留。

副作用在决策明确时内联发生：

- **根据不在 `CONTEXT.md` 中的概念命名深化模块？** 将该术语添加到 `CONTEXT.md`——与 `/grill-with-docs`（见 [CONTEXT-FORMAT.md](../grill-with-docs/CONTEXT-FORMAT.md)）相同的纪律。如果文件不存在就懒创建。
- **在对话中锐化一个模糊术语？** 立即更新 `CONTEXT.md`。
- **用户用 load-bearing 原因拒绝候选方案？** 提供一个 ADR，框架为：_"要我将其记录为 ADR 以便未来的架构审查不会重新建议它吗？"_ 仅在原因确实会被未来探索者需要以避免重新建议相同的事情时才提供——跳过临时原因（"现在不值得"）和不言自明的原因。见 [ADR-FORMAT.md](../grill-with-docs/ADR-FORMAT.md)。
- **想探索深化模块的替代接口？** 见 [INTERFACE-DESIGN.md](INTERFACE-DESIGN.md)。
