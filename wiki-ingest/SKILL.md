# AI-Wiki 内容摄入

将外部内容（粘贴文本、文件、URL 描述、学习材料）导入 AI-Wiki 笔记库，支持归档模式和学习模式。

## 模式选择

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| `archive` | 默认模式；保存资料、收录内容 | 按内容类型路由到 PARA 目录，创建笔记 |
| `learn` | 用户说要"学习"、导入学习材料、准备学习 | 路由到 PARA 目录 + 分解学习单元 + 生成测验素材 |

用户不指定时默认使用 `archive` 模式。

## 步骤

### 1. 接收内容

接受用户提供的：
- 粘贴文本
- 文件内容
- URL 描述
- 文档/代码库内容
- 学习材料

### 2. 分析内容类型与主题

判断内容属于哪种类型，同时识别是否包含学习意图。

### 3. 确定目标目录

使用内容路由规则：

| 内容类型 | 目标目录 | 模板 | frontmatter type |
|---------|---------|------|-----------------|
| 无法分类 | `01_收件箱/` | 收件箱模板.md | inbox |
| 知识/参考资料 | `05_资源/` | 资源模板.md | resource |
| 书籍 | `06_媒体/读书/` | 读书模板.md | book |
| 媒体体验 | `06_媒体/` | 媒体模板.md | media |
| 人物 | `07_人物/` | 人物模板.md | person |
| 项目想法 | `03_项目/` | 项目模板.md | project |
| 领域责任 | `04_领域/` | 领域模板.md | area |
| 有明确目标的学习计划 | `03_项目/` | 项目模板.md | project |
| 长期责任领域知识 | `04_领域/` | 领域模板.md | area |
| 不确定 | `01_收件箱/` | 收件箱模板.md | inbox |

### 4. 创建笔记（archive 模式）

- 复制 `00_系统/模板/` 中对应模板
- 填写 frontmatter（仅使用合法枚举值）
- 填写内容区域
- 添加相关链接（知识笔记：1-3 高置信链；执行笔记：→README/MOC）
- 更新目标目录 README `## 导航入口`

### 5. 创建学习体系（learn 模式）

在 archive 模式基础上增加：

#### 5a. 分解学习单元

- 将内容按主题分解为独立笔记
- 每个笔记基于对应模板创建
- 建立笔记间的学习路径链接（通过 `## 相关链接`）

#### 5b. 创建学习体系

- 主笔记作为学习概览，放到 `05_资源/` 下
- 子主题笔记按需创建
- 每个笔记包含 `## 相关链接` 连接前后学习单元

#### 5c. 生成测验素材（可选）

- 从内容中提取关键概念
- 生成问答对存入笔记的专用 section
- 标注难度等级：基础 / 中级 / 高级

#### 5d. 输入模式

| 模式 | 处理流程 |
|------|---------|
| 文档模式 | 输入文本/文档 → 按章节拆分 → 每章节一个资源笔记 → 串成学习路径 |
| 代码库模式 | 分析代码结构 → 按模块/功能拆分 → 每个模块一个资源笔记 → 标注代码路径 |

### 6. 批量处理

多个条目时：
- 按类型分组展示路由方案
- 用户确认后批量创建
- 汇总报告

## 规则

- 必须使用 `00_系统/模板/` 中的模板
- 禁止凭记忆填写 frontmatter — 必须从模板复制
- frontmatter 修改使用 `patchField`/`patchFields`，禁止使用 `processFrontMatter`
- 仅使用合法枚举值：type、状态、收件类型、媒体类型、优先级等
- 路由到现有 PARA 目录，绝不创建新的顶层目录
- 禁止自动分类旧笔记
- 创建文件后更新对应 README 导航

## 枚举值参考

所有 frontmatter 字段的合法值定义在 `.obsidian/types.json` 的枚举注册表中。创建笔记前必须确认所用值在注册表中存在。
