# AI-Wiki 复盘辅助

汇总指定周期内的日记、事件、待办、OKR 进度，生成结构化复盘草稿。

## 触发场景

- "帮我做周复盘"
- "本月复盘"
- "季度回顾"
- "回顾一下最近"
- "总结这周/这月"

## 步骤

### 1. 确定复盘周期

| 用户输入 | 时间范围 | 日记路径 | 事件路径 |
|---------|---------|---------|---------|
| 周复盘 | 本周一到今天 | `02_日常/日记与复盘/每日/YYYY-MM-DD.md` | `02_日常/事件/` |
| 月复盘 | 本月1日到今天 | 同上 | 同上 |
| 季度复盘 | 本季度第一天到今天 | 同上 | 同上 |
| 自定义 | 用户指定起止日期 | 同上 | 同上 |

### 2. 汇总日记内容

扫描周期内所有日记文件，提取：
- 日常记录的关键事项
- 情绪/状态标记（如有）
- 反复出现的主题或问题
- 提到的待办/项目进展

### 3. 汇总事件

扫描 `02_日常/事件/` 中日期在周期内的事件：
- 已完成事件（completed 有值）
- 未完成/延期事件
- 按类型分类（如有的话）

### 4. 汇总待办池

扫描 `03_项目/待办池/` 中所有条目：
- 已完成（状态为已完成）
- 进行中（等级 !!!/!!/!/空）
- 新增的待办
- 过期待办（create date 远早于当前且未完成）

### 5. 对齐 OKR 进度

读取 `02_日常/OKR/` 下的 OKR 结构：
- 找到当前活跃的 OKR（未标记完成）
- 对比周期内的进展
- 标注推进中的 KR 和停滞的 KR

### 6. 检测异常信号

- 超过 14 天未更新的进行中项目（`03_项目/进行中/`）
- 超过 30 天未更新的领域笔记（`04_领域/`）
- 长期待在收件箱未处理的条目（`01_收件箱/`）
- README 导航断链（引用了不存在的文件）

### 7. 生成复盘草稿

基于 `00_系统/模板/复盘模板.md` 创建复盘笔记，包含：

```
## 周期概况
[一句话总结]

## 完成事项
- [关键完成项列表]

## 进行中
- [进展中的项目和待办]

## OKR 进展
- [各 KR 状态]

## 异常与风险
- [检测到的异常信号]

## 下周期重点
- [基于本周数据推断的建议重点]
```

### 8. 更新导航

更新 `02_日常/日记与复盘/` 的 README 导航入口。

## 规则

- 使用复盘模板创建，禁止凭记忆手写 frontmatter
- 仅汇总已有数据，不编造未记录的内容
- 异常信号基于事实标注（日期、状态），不做主观判断
- "下周期重点"是建议性的，明确标注为建议
- frontmatter 修改使用 `patchField`/`patchFields`
- 更新对应 README 的 `## 导航入口`
- 复盘笔记保存到 `02_日常/日记与复盘/` 下对应周期目录

## 输出位置

| 复盘类型 | 保存路径 |
|---------|---------|
| 周复盘 | `02_日常/日记与复盘/周复盘/` |
| 月复盘 | `02_日常/日记与复盘/月复盘/` |
| 季度复盘 | `02_日常/日记与复盘/季度复盘/` |

如果对应子目录不存在，先询问用户是否创建。

## 枚举值参考

所有 frontmatter 字段的合法值定义在 `.obsidian/types.json` 的枚举注册表中。
