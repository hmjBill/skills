# AI-Wiki 需求文档生成

> **使用边界**：本技能的产出需写入 AI-Wiki 时，应由 Wiki Agent 执行落库；Coding Agent 使用时应先把 PRD 草稿交给用户确认，再由用户或 Wiki Agent 归档。

将对话中的想法或需求整理为结构化的项目需求文档，归档到 AI-Wiki 的 `03_项目/` 系统。

## 定位

基于 to-prd skill 适配 AI-Wiki 项目管理结构。

## 工作流

### 1. 收集上下文

从当前对话中提取：
- 需求描述
- 约束条件
- 项目目标
- 相关背景

### 2. 确定测试 seam

先确定将在哪些 seam（接缝）上测试这个功能，再写文档：

- 优先复用现有 seam，而不是新建 seam
- 尽量使用最高的 seam
- 如果需要新 seam，在你能够提出的最高点提议
- 整个代码库中的 seam 越少越好——理想数量是一个

与用户确认这些 seam 符合预期。

### 3. 结构化需求文档

使用 `00_系统/模板/项目模板.md` 创建文档。

**Frontmatter 填写：**

```yaml
type: project
状态: 进行中
项目名称: <名称>
目标: <目标描述>
开始日期: <YYYY-MM-DD>
结束日期: <YYYY-MM-DD 或空>
相关领域: <领域列表>
tags:
  - <标签>
```

**正文结构：**

- `## 目标` → 项目目标和完成标准
- `## 进展` → 初始需求分解
- `## 备注` → 需求文档详细内容（见下方模板）

### 4. 路由决策

| 情况 | 目标目录 | 模板 | 状态 |
|-----|---------|------|------|
| 有明确目标和截止日期 | `03_项目/进行中/` | 项目模板.md | 进行中 |
| 仅是想法/灵感 | `01_收件箱/` | 收件箱模板.md | 收件类型: 灵感 |
| 需要讨论 | `01_收件箱/` | 收件箱模板.md | 收件类型: 待处理 |

### 5. 添加相关链接

项目模板包含 7 个链接子区域：
- 上层归属 / 相关笔记 / 相关项目 / 相关OKR / 相关事件 / 相关人物 / 其他

链接来源：
- 相关领域 README（`04_领域/`）
- 相关 OKR（`02_日常/OKR/`）
- 1-3 个高置信度链接

### 6. 更新导航

更新目标目录 README 的 `## 导航入口`。

最小示例（表格或用列表形式均可，沿用目标 README 的现有风格）：

```markdown
## 导航入口

| 文档 | 说明 |
|------|------|
| [[03_项目/进行中/示例项目]] | 一句话说明 |
```

### 7. 报告

通知用户文件创建位置和内容概要。

## PRD 模板结构（`## 备注` section 内）

```markdown
### 问题陈述
要解决什么问题，为什么现在要做。

### 解决方案
高层方案描述。

### 用户故事
作为 X，我希望 Y，以便 Z。

### 实施决策
技术选型、架构方向等关键决定。

### 测试决策
测试相关决定，包括：
- 好测试的标准（只测试外部行为，不测试实现细节）
- 哪些模块会被测试
- 测试的既有先例（代码库中类似类型的测试）

### 范围外
明确不做的内容。

### 补充说明
风险、依赖、时间线等。
```

## 规则

- 有明确目标的 PRD 始终使用项目模板.md
- 模糊想法使用收件箱模板.md
- 状态仅使用合法枚举值：进行中 / 已完成 / 废弃 / 暂停 / 搁置
- 创建文件后更新 `03_项目/进行中/README.md` 或 `01_收件箱/README.md` 导航（格式示例见「更新导航」）
- 不自动创建 GitHub Issues（除非用户明确要求）
- 知识笔记添加 1-3 个高置信度的跨领域链接
