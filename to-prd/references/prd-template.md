# PRD 模板

复制到 `docs/prd/<feature-slug>.md` 后逐段填写。`<>` 是占位符，不要留空段。

```markdown
# <功能名> · 需求

更新：YYYY-MM-DD · 状态：<草稿/已确认/实现中/已完成>
关联：GOAL.md · <相关 PRD 或 ADR 路径>

## 问题

要解决什么问题，为什么现在做。写现象，不写方案。

## 方案

高层做法，三到五句。不写实现细节。

## 用户故事

- 作为 <角色>，我希望 <行为>，以便 <目的>。（已确认）
- 作为 <角色>，我希望 <行为>，以便 <目的>。（AI 假设，待确认）

## 行为与边界

| 场景 | 期望行为 | 状态 |
| --- | --- | --- |
| 正常路径 | | 已确认 |
| 空输入 | | 待定 |
| 超大输入 | | AI 假设 |

明确不做：<边界外的行为>。

## 实施决策

只记会影响外部行为或后续改动的决定。

| 决定 | 理由 | 日期 |
| --- | --- | --- |

## 测试决策

- 在哪个 seam 上验证：<文件/接口/命令>
- 好测试的标准：只测外部行为，不测实现细节
- 既有先例：<仓库内类似的测试路径>

## 验收判据

| # | 判据 | 判定方式 | 状态 |
| --- | --- | --- | --- |
| 1 | | `<命令>` 退出码 0 | 已确认 |
| 2 | | <可观察结果> | 待定：需要 <什么> 才能判 |

## 范围外

- <明确不做> —— 留到 <何时/哪个 PRD>

## 变更记录

- YYYY-MM-DD <改了什么> —— 因为 <原因>；影响 <哪些段落>
```

## 填写要点

| 段落 | 常见错误 | 正确做法 |
| --- | --- | --- |
| 问题 | 写成了方案 | 只描述现象和影响面 |
| 用户故事 | 一条覆盖太多 | 一条一个行为，能单独验收 |
| 行为与边界 | 只写正常路径 | 至少三条：正常、空、异常 |
| 测试决策 | 写"要加测试" | 指明 seam 和既有先例路径 |
| 验收判据 | 用形容词（"流畅""好看"） | 换成命令、阈值或打分表 |
| 范围外 | 空着 | 至少一条，否则范围会膨胀 |
