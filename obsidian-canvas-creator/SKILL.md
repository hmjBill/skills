# Obsidian Canvas 创建器

将文本内容转换为结构化的 Obsidian Canvas 文件，支持思维导图和自由布局。

> **使用边界**：本技能主要面向 Wiki Agent 使用。Coding Agent 不应直接写入 AI-Wiki；如需在笔记库中创建画布，应先把 Canvas 草稿交给用户确认，再按用户或笔记库约定归档（AI-Wiki 由 Wiki Agent 落库）。

本技能在原 obsidian-canvas-creator 基础上增加了笔记库的存放位置、链接规范和典型场景说明。

## 使用场景

- 用户请求从文本创建画布、思维导图或可视化图表
- 用户希望以空间方式组织信息
- 用户提到 Obsidian Canvas 或类似可视化工具
- 将结构化内容（文章、笔记、大纲）转换为可视化格式

## 核心工作流

### 1. 分析内容

阅读并理解输入内容：
- 识别主要主题和层级关系
- 提取要点、事实和支撑细节
- 注意已有结构（标题、列表、章节）

### 2. 确定布局类型

询问用户选择或从上下文推断：

**思维导图布局：**
- 从中心向外辐射
- 父子关系
- 清晰的层级
- 适用于：头脑风暴、主题探索、层级内容

**自由布局：**
- 自定义定位
- 灵活的关系
- 多种连接类型
- 适用于：复杂网络、非层级内容、自定义排列

### 3. 规划结构

**思维导图：**
- 确定核心概念（根节点）
- 规划主要分支（主话题）
- 组织次级分支（子话题）
- 定位叶节点（详情）

**自由布局：**
- 分组相关概念
- 识别连接模式
- 规划空间区域
- 考虑视觉流向

### 4. 生成画布

按照 Canvas 规范创建 JSON：

**节点创建：**
- 分配唯一的 8-12 字符十六进制 ID
- 根据内容长度设置合适尺寸
- 应用一致的配色方案
- 确保坐标不重叠

**边创建：**
- 连接父子关系
- 使用合适的箭头样式
- 为复杂关系添加标签
- 选择线条样式（层级用直线，交叉引用用曲线）

**分组（可选）：**
- 为相关节点创建视觉容器
- 使用柔和的背景色
- 添加描述性标签

### 5. 应用布局算法

**思维导图布局计算：**

详细算法参见 `references/layout-algorithms.md`。关键原则：

- 根节点居中于 (0, 0)
- 主节点径向分布
- 次级节点基于兄弟数量排列
- 最小间距：水平 320px，垂直 200px

**自由布局原则：**

- 从逻辑分组开始
- 各组之间保持清晰间距
- 跨组使用曲线边连接
- 平衡画布各区域的视觉重量

### 6. 验证与输出

输出前：

**验证清单：**
- 所有节点有唯一 ID
- 坐标不重叠（检查距离 > 节点尺寸 + 间距）
- 所有边引用有效的节点 ID
- 分组（如有）有标签
- 颜色使用一致格式（十六进制或预设编号）
- JSON 正确转义（引号规则见「关键规则」第 1 条）

**输出格式：**
- 完整、有效的 JSON Canvas 文件（文件内不含额外说明文本）
- 保存后向用户报告保存位置（路径与简要说明）
- 可直接导入 Obsidian

## 节点尺寸指南

**基于文本长度的尺寸：**
- 短文本（<30 字符）：220 × 100 px
- 中等文本（30-60 字符）：260 × 120 px
- 长文本（60-100 字符）：320 × 140 px
- 超长文本（>100 字符）：320 × 180 px

## 配色方案

**预设颜色（推荐）：**
- `"1"` — 红色（警告、重要）
- `"2"` — 橙色（待办事项）
- `"3"` — 黄色（问题、备注）
- `"4"` — 绿色（正面、已完成）
- `"5"` — 青色（信息、详情）
- `"6"` — 紫色（概念、抽象）

**自定义十六进制颜色：**
用于品牌一致性或特定主题。始终使用大写格式：`"#4A90E2"`

## 关键规则

1. **引号处理（统一规则）：**
   - 中文双引号（“ ”）→ 『』
   - 中文单引号（‘ ’）→ 「」
   - 英文双引号（"）在 JSON 字符串中必须转义为 `\"`，或改用 『』

2. **ID 生成：**
   - 8-12 字符随机十六进制字符串
   - 所有节点和边的 ID 必须唯一

3. **Z 轴顺序：**
   - 先输出分组（底层）
   - 然后是子分组
   - 最后是文本/链接节点（顶层）

4. **间距要求：**
   - 节点中心之间最小水平间距：320px
   - 节点中心之间最小垂直间距：200px
   - 计算时需考虑节点尺寸

5. **JSON 结构：**
   - 顶层仅包含 `nodes` 和 `edges` 数组
   - 无额外包装对象
   - 输出中不含注释

6. **禁止 Emoji：**
   - 不要在节点文本中使用任何 Emoji 符号
   - 使用颜色编码或文本标签进行视觉区分

## 示例

### 简单思维导图请求
用户："创建一个关于太阳系行星的思维导图"

流程：
1. 确定中心："太阳系"
2. 主要分支：内行星、外行星、矮行星
3. 次级节点：各行星及关键事实
4. 应用径向布局
5. 生成间距合理的 JSON

### 自由布局内容请求
用户："把这篇文章转成画布" + [文章文本]

流程：
1. 提取文章结构（引言、正文各节、结论）
2. 识别关键概念和关系
3. 空间上分组相关章节
4. 用带标签的边连接
5. 应用自由布局，划分清晰区域

## 高质量画布技巧

1. **保持文本简洁**：每个节点应可快速扫读（首选 <2 行）
2. **使用层级**：按重要性和关系分组
3. **平衡画布**：均匀分布节点，避免聚集
4. **策略性配色**：用颜色编码语义，而非仅作装饰
5. **有意义的连接**：只为明确关系的节点添加边
6. **在 Obsidian 中测试**：验证输出能正确打开

## 常见陷阱与避免方法

- 节点重叠（始终检查距离）
- 引号转义不一致（会导致 JSON 解析失败）
- 分组缺少标签（会导致侧边栏导航问题）
- 节点中文本过多（长内容应使用文件节点）
- ID 重复（每个 ID 必须唯一）
- 孤立节点未连接（除非是故意为之）

## 笔记库画布应用

### 存放位置（示例目录，按你的笔记库结构替换）

Canvas 文件（.canvas）的存放位置因笔记库而异；以下仅为示例映射，请按你的笔记库结构替换：

- 知识结构图 → 资源类目录（示例：`05_资源/` 对应子目录）
- 项目架构图 → 项目类目录（示例：`03_项目/` 对应项目目录）
- 领域关系图 → 领域类目录（示例：`04_领域/` 对应领域目录）
- 读书思维导图 → 媒体/读书目录（示例：`06_媒体/读书/` 对应笔记旁）
- 如果不确定 → 放到笔记所在目录

### 创建后操作
- Canvas 文件不需要 frontmatter
- 如果 Canvas 是某笔记的附属可视化，在笔记的 ## 相关链接 中添加链接
- 如果 Canvas 是独立知识可视化，在目录 README 的 ## 导航入口 中添加链接
- 链接格式：`[[路径/文件名.canvas|显示名]]`

### 典型场景（示例目录，按你的笔记库结构替换）
1. **论文结构图**: 展示论文各章节关系和核心论点链 → 存入媒体/读书目录（示例：`06_媒体/读书/`）
2. **项目架构图**: 展示项目组件/里程碑关系 → 存入项目目录（示例：`03_项目/进行中/`）
3. **知识体系图**: 展示领域内概念关系网络 → 存入领域目录（示例：`04_领域/`）
4. **OKR 分解图**: 展示 OKR 层级关系（只读展示，不替代 DataviewJS）→ 存入 OKR 目录（示例：`02_日常/OKR/`）

### 注意事项
- Canvas 文件中引用笔记使用 wikilink 节点类型（type: "link"）
- 不要为 Canvas 创建新的顶层目录
- 不要在系统目录或受控信息目录中创建 Canvas（示例：`00_系统/`、`09_受控信息/`）
