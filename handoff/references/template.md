# 交接文档（handoff）

换会话或换机器前写。目标：**下一个 agent 只读这一份就能接着做。**

```markdown
# 交接 · <一句话主题>

更新：YYYY-MM-DD HH:MM · 分支：<branch> · 最近提交：<sha>

## 目标与完成判据

<要做什么；做完怎么算对，最好指向一条命令>

## 已做的决策

- <决定> —— 因为 <理由>

## 已排除的方案

- <方案> —— 因为 <理由>（**不要重复试**）

## 当前真实状态

- 已改文件：<路径列表>
- 已跑验证：<命令 + 退出码>（原样，不概括）
- 未验证项：<项> —— 需要 <谁/什么条件>

## 下一步

1. <具体动作>
2. <具体动作>

## 建议技能

- `<技能名>` —— 为什么它会用到
```

## 硬规则

- **来源必须是真实状态**：写之前实际执行 `git status`、`git log -1`，不要凭记忆。
- 跑不了的标 `未验证`，不要写成"应该没问题"。
- 不复制已在别处的内容（PRD、issue、diff），只给路径或 URL。
- 不写 API key、token、密码、PII。

## 什么时候不该写交接文档

| 处境 | 正确动作 |
| --- | --- |
| 同一任务，只是对话太长 | 压缩上下文，别开新会话 |
| 走错了路 | **回到出错之前**，不要把错误尝试写进摘要 |
| 已压缩多次、开始重复问已回答的问题 | 写交接文档 + 换新会话 |
| 换新任务 | 直接开新会话，不需要交接 |
