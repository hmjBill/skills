# 会话交接

## 1. 先三分桶

- **drop** — 能再取回的：大文件读、测试日志、搜索结果、已废弃的尝试。
- **summarize** — 只属于本次会话的剧情：当前在哪、下一步、未解 bug、最近碰过的文件。
- **写文件** — 丢了会疼的：决策及理由、验收标准、长期规则、被拒绝的审查发现。

第三桶必须现在就写，不能靠压缩兜底。

## 2. 来源必须是真实状态

写之前实际执行并引用：`git status`、`git log --oneline -10`、当前分支与 diff、跑过的验证命令及其**真实最新输出**。无法核实的标 `未验证`，不要凭对话记忆补全。

## 3. 动作四分叉

| 处境 | 动作 |
| --- | --- |
| 同一任务，历史只是太长 | 压缩，并在指令里声明保留什么、下一步是什么 |
| 走错了路 | **rewind 到出错之前**，不要压缩——别把错误尝试写进摘要 |
| 已压缩多次且开始漂移、重复问已回答的问题、破早先约束 | 写本文档 + 换新会话 |
| 换新任务 | 直接开新会话 |

## 4. 文档内容

保存到宿主临时目录下的新建文件（Windows 用 `[IO.Path]::GetTempFileName()` 取路径，macOS/Linux 用 `mktemp -t handoff-XXXXXX.md`）；文件已有内容时先读取再覆盖。

必须含：

- 目标，以及“完成”的判据
- 已做的决策及理由
- **已排除的方案及原因**
- 当前真实状态（分支、未验证项）
- 下一步

另加“建议技能（suggested skills）”小节，列出下一个 agent 应接手的技能名（按当前宿主的技能调用约定）。

## 5. 脱敏与引用

不写 API key、密码、PII、token。不复制已存在于其他 artifact（AI-Wiki 中的 PRD、issue、diff）的内容，改为通过路径或 URL 引用。

如果用户传递了参数，将其视为对下一个会话关注内容的描述，据此定制文档。
