# 快速安装与复用

仅在首次安装、命令缺失或用户新请求
profile 时阅读本文。已能正常工作的安装无需重装、预热、重启
浏览器，也无需在每个任务前重新注册。

## 已安装：直接开始任务

`command -v agent-browser` 检查命令是否可用，且不会
打开 Chrome。若命令存在，遵循操作员技能：保留唯一会话
和所请求的账户，然后 `open` 实际任务 URL。执行敏感操作前，
先验证页面上可见的账户。完成后关闭你的任务。

挂接失败并不构成安装缺失的证据。保留其
确切错误，对照已安装的 wrapper、broker 和扩展进行诊断；
不要在活动浏览器上覆盖安装，也不要轮换 profile。

## 新机器：代理准备，用户批准

本 fork 当前的目标环境是 Windows Stable Chrome + WSL。它还不是
可移植的一键安装器。从 npm 安装上游 `agent-browser`，
或仅复制本技能，都不会安装本 fork 的私有传输组件。

负责安装的代理应使用随附的源码和构建说明，
一次性准备好受支持的各个部分：

1. 确认本机实际的 Windows 用户、Stable Chrome、WSL 发行版、
   仓库位置以及所请求的 Chrome profile。复用现有 profile；
   绝不复制 profile，也绝不使用他人机器上的本地配置。
2. 绑定一组一致的 engine、wrapper、broker 和 relay 修订版本。使用
   仓库的 `scripts/agent-browser-engine-build.md` 和 engine 获取
   辅助工具，以取得经过验证的产物和许可证。它们准备的是产物，而非
   完整安装好的浏览器。安装前先消除任何 pin/recipe 不匹配；
   经过验证的本地安装使用该 recipe 中选定的 engine。
3. 准备 Windows 原生宿主和传输扩展。注册前检查确切的
   宿主可执行文件和观察到的扩展 ID。受支持的
   首装入口是 `native-host/install.ps1`，必需输入为
   `-ExtensionId`、`-HostExecutablePath`、`-WslDistro` 和 `-WslBridgePath`。
   它只注册当前用户的宿主，并有意拒绝
   已存在的注册/安装目录。不要为了
   绕过该拒绝而卸载正常工作的宿主。升级需要单独验证的
   针对该确切已安装版本的迁移和回滚方案，而不是走这条首装路径。
4. 准备好确切的传输扩展，然后引导用户在每个被请求的 Chrome profile
   中完成一次性的加载与配对操作。代理负责准备
   文件并确定确切的 profile；不代用户自动点击同意。
   扩展和配对是按 profile 进行的，不会被同一 Chrome 中
   的每个 profile 自动共享。只注册被请求的 profile。
5. 通过受支持的
   broker 确认原生连接和账户映射，然后验证普通 CLI 路径：打开一个无害的、
   自己拥有的后台标签页，读取其紧凑快照，关闭它，并在不干扰
   现有标签页的情况下验证清理完成。只保存非机密的安装证据和本地账户别名。
   扩展图标存在或安装器显示成功都不构成该证明。

不要要求用户定位日志、重建二进制文件或还原可访问的
配置。只询问缺失的选项，以及真正只有 Chrome/用户才能给出的同意。
普通任务应复用注册；复用时出现新的提示说明
需要诊断，而不是再来一轮点击。

## 技能与运行时属于一体

将这份操作员载荷安装到所选代理宿主发现技能的位置，
并让它的参考文件与之一同保留。Codex、Claude Code 以及其他具备命令能力的代理
可以使用同一套说明；发现路径和调用方身份集成
因宿主而异。在验证其普通的
归属/清理路径之前，不要声称新的代理宿主可用。

机器特定的账户别名要保持私密。可分发的技能只说明
如何选择本地映射的账户；不得随附他人的邮箱、
profile 路径、注册数据或凭据。

经过验证的运行时升级之后，更新技能的可用性说明，使其与
已安装的命令一致。仅有候选证明不足以启用某项功能。

**绝不要将重置 Chrome、其他扩展、MetaMask、钱包存储、Cookie、
凭据或硬件钱包/USB 设置作为安装捷径。**
