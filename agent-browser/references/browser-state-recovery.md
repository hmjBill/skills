# 受保护的浏览器与扩展状态边界

本参考是一条停止/转交规则，不是许可，也不是修复流程。
普通的私有 Agent Browser 路径只控制 HTTP(S) 任务标签页。它不
授予检查或改动 Chrome profile 文件、扩展存储、
Cookie、凭据、MetaMask、钱包、USB 或硬件钱包行为的权限。

## 若预期状态看似缺失

- 将引导页、已登出的页面、缺失的扩展状态或新的
  批准提示视为真实的红灯。不要为了让该症状消失而
  创建/导入/重置任何东西。
- 以 Windows Stable Chrome 实际的 `User Data` 根目录和确切的已注册 profile
  为准。绝不用 `ChromeCDP`、复制/临时 profile 或
  替代的 `--user-data-dir` 来顶替。
- 不要仅为重试而重启 Chrome、WSL、broker 或扩展，
  也不要在没有因果证据变化的情况下重复相同的浏览器操作。
- 绝不打印、导出、复制或持久化 Cookie、令牌、密码、保险库、助记
  词、私钥、一次性验证码或恢复密钥。
- 停止普通浏览器工作，并将一个单独授权的
  状态恢复任务交给维护者。该工作
  必须绑定确切的当前版本/profile/源（origin），保留有范围的预映像（preimage），
  指定回滚消费方，并证明字面意义上的全新生命周期。

## 历史原因，而非当前流程

在 8 月 26 日的 MetaMask 13.44/13.45 恢复中，扩展在界面上可见以及
密钥数量并不能证明钱包可用。证据显示存在版本特定的分裂
controller 状态，且已加载的扩展代码可能在写入之后重写存储。
因此，立即的哈希匹配只证明了写入边界；正常的
新鲜解锁/账户界面才是字面结果。这段历史禁止那些
失败的捷径。在其能支持未来任何状态操作之前，
必须针对已安装版本重新验证。

对于真正只有用户才能提供的输入，保留确切的任务会话。让用户
选择其标签页，或仅在获得许可时使用文档化的 `foreground --input-boundary TYPE` 操作。
输入之后，在适用时使用带完全相同账户、
会话和 `--current-tab` 前缀的 `background`。返回先前保存的
应用或标签页以焦点历史未变为条件；取消、拒绝、
未确认的结果或未发生移交都不保证焦点。绝不重试或强制
聚焦，也绝不通过聊天或 shell 传递机密。
